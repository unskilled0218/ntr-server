# Release v0.2.13

- [Changes](#changes)
- [Upgrade](#upgrade)

## Changes

- Deliver concurrent external catalog-only changes to the initiating client's SSE subscription. Preserve filtering for proven self-only writes and avoid duplicate polling events.
- Synchronize HA sidecar contents before replacement and the containing directory afterward. Apply this boundary to migration, move admission, verified target identity, completion, and recovery; do not advance dependent HA writes after a persistence failure.
- Add notification, persistence-ordering, migration-failure, and post-rename recovery regressions. Keep file-backed task/note/label writes, client APIs, and explicit no-replay recovery unchanged.

## Upgrade

HA metadata saves require Unix and a persistent filesystem/storage stack that honors file and directory fsync. Back up the sidecar, validate storage semantics, and inspect uncertain operations before explicit recovery. The schema remains 2 and no client upgrade is needed beyond existing multi-list requirements. See [durability limits](../home-assistant.md#metadata-durability). Prepared locally; no image publication or deployment is implied.

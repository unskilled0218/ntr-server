# Release v0.2.12

- [Changes](#changes)
- [Upgrade](#upgrade)

## Changes

- Discover all visible HA to-do lists as projects, including empty lists. Preserve entity-qualified numeric identity across duplicate UIDs and restarts.
- Add explicit list routing and confirmed copy/verify/delete moves with a durable recovery journal. Preserve native descriptions, status, due values, and ntr lifecycle metadata. Recovery never automatically repeats HA mutations.
- Add Local To-do creation, registry display-name renaming, and confirmed empty-only Local To-do deletion. Require `HA_MANAGE_LISTS=true` and an HA admin token; keep the default list protected.
- Keep server-only credentials, verified HTTPS/WSS trust, file/local task backends, and Markdown notes unchanged. Prepared locally, not published.

## Upgrade

Use app 0.15.32 or later for list-aware controls. Back up `HA_METADATA_FILE` before upgrading: matching schema 1 maps migrate atomically to schema 2, preserving IDs and lifecycle data. Schema 2 binds the normalized HA URL; it is not readable by older servers. To roll back, stop ntr and restore a matching pre-upgrade backup, never silently reset the map. A pending journal can contain task content and requires private storage. See [HA safety](../home-assistant.md#safety-and-compatibility).
